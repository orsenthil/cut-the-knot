Mazes

Puzzle by Alexander Bogomolny (cut-the-knot.org)

What it shows: a rectangular grid becomes a maze when Prim's or Kruskal's algorithm grows a spanning tree of passages, then a depth-first search finds the way from start to end.
How to play: set the grid size, optionally carve the shape, then Create a maze (step by step or all at once) and Solve it.

Look for the math

A maze with no loops is a tree drawn on the grid graph: every cell is reachable from every other, and there is exactly one path between any pair. For any connected graph that means |V| = |E| + 1.

Spanning trees from greedy choices

Both Prim's and Kruskal's algorithms build a spanning tree by always taking the next edge that does not create a cycle. Prim grows one connected piece from the start cell; Kruskal merges many tiny trees. The applet assigns nearly-random weights to the grid edges so the greedy choice has something to compare.

Maximum, not minimum

The classic textbook story picks the lightest safe edge and proves the result is a minimum spanning tree. This applet's sorted edge list compares with weight > weight, so it actually grows a maximum spanning tree. The same exchange argument works either way: swapping the chosen edge for any heavier (or lighter) edge on the cycle it would close cannot improve the total.

Solving by depth-first search

Once the passages are a tree, there is only one route from start to end. Depth-first search walks forward until it hits a dead end, then retreats to the last junction with an unused passage — the maze-walking method of "keeping one hand on the wall," made precise.

Try Prim and Kruskal on the same grid (press Reset for new random weights). The passages differ, but both leave exactly one path from the blue start to the red end.

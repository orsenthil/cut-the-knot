    Look for the math

    This is a browser version of Alexander Bogomolny's applet "Aliquot game", after a puzzle in D. L. Silverman's Your Move (McGraw-Hill, 1971). An aliquot part of a number is a proper divisor: any divisor except the number itself. So 12 has the aliquot parts 1, 2, 3, 4 and 6; a prime has only 1; and 1 has none at all, which is exactly why being handed 1 loses.

    An odd number hides no even divisor

    Say d divides an odd number n, so n = d × k. If d were even then n would be even as well. So every divisor of an odd number is odd — and odd minus odd is even:

    From an odd number, every legal move hands your opponent an even number.

    You have no choice in the matter. That is the half of the game you cannot escape.

    So the game is nothing but parity

    The other half is just as blunt: 1 is an aliquot part of every number above 1, so from an even number you can always leave n − 1, which is odd. Now run induction up from the bottom:

    n = 1: no move, so the player facing it has lost.
    n even: take 1 off and hand over an odd number, which is lost. So even is won.
    n odd: every move hands over an even number, which is won for your opponent. So odd is lost.

    Nothing about the number matters except its parity — not how big it is, not how it factorises. The port's logic test solves the whole game backwards from 1 up to 2000, position by position, and the answer is always "even wins".

    How the computer keeps a straight face

    Taking 1 every single turn would win and would also give the secret away by the second move. So the applet's opponent divides the twos out of the number, takes the smallest divisor of 3 or more left over, and only falls back to 1 when nothing is left over:

    48 = 24 × 3, so it takes 3 and leaves 45.
    50 = 2 × 52, so it takes 5 and leaves 45.
    64 = 26 has no odd part, so it takes 1 and leaves 63.

    Each of those is odd, because an odd divisor taken off an even number must leave an odd number. The one shape with nothing to hide behind is a power of two, whose only odd aliquot part is 1. Bogomolny suggests a harder variant on his page — you may not take 1 off a composite number — and powers of two are exactly where that rule bites: from 4, 8, 16, … you would be forced to leave an even number behind.

    Start at 99. You are lost before you move, so see how long you can make the computer work for it. Then start at 64 and watch which single number it takes.
